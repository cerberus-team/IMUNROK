# UI 꾸러미 — 옹고집 쪽에서 물린 것과 고쳐 주었으면 하는 것

`IMUNROK_UI.unitypackage` 를 옹고집 프로젝트에 그대로 임포트해 보고 적는다.
**임포트 자체는 깨끗했다** — 컴파일 오류 없음, `IMUNROK.Ui` 와 `IMUNROK.Common` 두 어셈블리가 나란히 선다.

아래는 **꾸러미 쪽에서 고쳐 주면 좋을 것**이다. 우리 쪽에서 막을 수 있는 것은 이미 막았고,
그건 「우리가 한 일」에 적어 두었다.

---

## 1. 마이크 임자가 정해져 있지 않다 ★

**무엇이 물리나**

옹고집에는 마이크를 원하는 데가 셋이다.

| 누가 | 언제 |
|---|---|
| `NoiseMeter` (잠행 소리계) | 조사 내내 **계속 쥔다** |
| `InterrogationController` (심문) | 창이 열린 동안 |
| 꾸러미의 `VoiceInput` | 「누르고 말하기」 동안 |

윈도에서 `Microphone.Start` 는 **같은 장치를 다시 열면 앞의 것을 끊는다.**
소리계가 쥔 채로 대화창이 녹음을 시작하면 **소리계의 눈금이 오류 한 줄 없이 죽는다** —
잠행 중에 소리를 아무리 내도 아무도 안 온다. 반대로 소리계가 다시 잡으면
받아쓰기가 끊긴다.

`VoiceInput` 이 대기 중에는 안 잡는 것은 잘 되어 있다(녹음 시작 때만 연다).
문제는 **누가 우선인지 아무도 안 정한다**는 것이다.

**제안**

꾸러미가 **이름 없는 걸쇠**를 하나 두고, 녹음을 시작·끝낼 때 올렸다 내려 주면 된다.

```csharp
// 꾸러미 안 어디든
public static class UiMic
{
    static int _n;
    public static bool Held => _n > 0;
    public static void Claim()  { _n++; }
    public static void Release(){ if (_n > 0) _n--; }
}
// VoiceInput 이 Microphone.Start 앞뒤에서 Claim / Release
```

**셈이라야 한다** — 참·거짓이면 둘이 겹쳐 쥐었다 하나가 놓을 때 나머지가 쥔 채로 걸쇠가 내려간다.
그리고 재생이 새로 시작될 때 `[RuntimeInitializeOnLoadMethod]` 로 **0으로 되돌려야** 한다
(도메인 리로드가 꺼진 프로젝트에서는 정적 값이 세션을 넘겨 산다 — 꾸러미 문서 §6에 그 이야기가 이미 있다).

> 우리 쪽은 같은 모양의 `IMUNROK.Common.MicHold` 를 이미 만들어 두었다.
> 꾸러미가 자기 걸쇠를 두면 우리가 그 둘을 이어 준다. 꾸러미가 우리 것을 알 필요는 없다.

## 2. 눈(카메라)을 `Camera.main` 하나로 잡는다 ★

**무엇이 물리나**

옹고집의 어전(인트로)은 **머리를 못 박은 씬**이다 — 연출이라 카메라가 어디를 보는지까지
짜 두었고, 헤드셋을 써도 카메라를 옮기지 않는다(손만 준다). 우리 쪽 표시는 `FixedView`.

`VrPanel`·`DebugToast` 는 `DebugWalkController` → 없으면 `Camera.main` 순으로 눈을 찾는데,
그런 씬에서는 **그 카메라가 사람의 목이 아니다.** 판이 「눈앞」이라 여기고 서는 자리가
실제 시선과 어긋난다.

**제안**

눈을 **주입받는 자리**를 하나 열어 달라.

```csharp
public static class UiEye { public static Transform Override; }
// VrPanel: UiEye.Override ?? DebugWalkController?.eye ?? Camera.main
```

한 줄이면 되고, 안 꽂으면 지금과 똑같이 돈다.

---

## 3. 하단바의 VR 각도가 **시선 기준**이다 ★

문서 §5: *「눈에서 아래로 −16°」*

어전은 시선이 **51° 숙어** 있다. 시선 기준으로 −16° 를 더하면 판이 **발밑으로 간다.**
같은 일을 우리도 겪었다 — 귀퉁이 단추를 「눈을 바라보게」 세웠더니 비스듬히 기울었고,
화면과 나란히(카메라 자세 그대로) 세워야 반듯했다.

**제안**: 아래로 내리는 각은 **수평 기준**으로 잡거나, 적어도 고를 수 있게 해 달라.
고개를 숙인 씬에서만 드러나는 종류라 평지에서 시험하면 안 보인다.

---

## 4. 글꼴 파일을 꾸러미가 들고 온다

**무엇이 물리나**

꾸러미가 `_Common/Art/Fonts/ChosunCentennial_ttf.ttf` 를 넣는다. 그런데 옹고집에는
같은 폴더에 **같은 서체의 `.otf`** 가 이미 있고, 그쪽 `.meta` 가 **git 에 들어 있다** —
즉 GUID 가 이미 팀의 것이고, 우리 씬 넷과 글꼴 에셋 한 장이 그것을 물고 있다.

그래서 지금은 **같은 서체가 두 벌**로 서 있다. 보이는 글자는 같지만 아틀라스가 둘이다.
(TMP 에셋이 Dynamic 이라 `.ttf` 를 지울 수도 없다 — 안 구워 둔 글자를 그 자리에서 굽는다.)

**제안**

꾸러미에 **글꼴 원본(.ttf)을 넣지 말고 구워 둔 TMP 에셋만** 넣는 쪽이 낫다.
원본은 지금도 공유폴더로 도는 물건이고, 프로젝트마다 서체 파일이 하나씩 늘어난다.

굳이 넣어야 한다면 **어느 파일이 정본인지 문서에 한 줄** 적어 달라 —
받는 쪽이 「내 것을 버릴까, 저쪽을 버릴까」를 매번 판단하게 된다.

---

## 5. 구워 둔 TMP 에셋이 한 겹 더 들어가 있다

`Fonts/Resources/TMP_*.asset` 은 `Fonts/` 보다 **한 겹 아래**다.
`.gitignore` 에서 흔히 쓰는 *「폴더를 한 번 열고 그 안에서 다시 거르는」* 방식은
**한 겹까지만 미치므로**, 받는 쪽에서 그 `.meta` 가 통째로 빠지기 쉽다.
그러면 clone 만 하고 꾸러미를 안 넣은 사람 손에서 **대화창 글씨가 통째로 빈다.**

우리는 확장자로 막는 쪽으로 고쳤다. **꾸러미 문서 §8 에 한 줄 적어 두면** 다음 사람이 안 밟는다.

---

## 6. `UiModeWatcher` 가 모든 씬에서 저 혼자 선다

`RuntimeInitializeOnLoadMethod` 로 자기 오브젝트를 만들고 F8 을 잡는다.
꾸러미 UI 를 **안 쓰는 씬**(우리 어전·조사청)에서도 선다. 크게 해로운 건 아닌데,

- 세션마다 콘솔에 한 줄 남는다
- F8 을 잡는다 (다른 데서 F8 을 쓰면 겹친다)

**제안**: 판이 하나라도 서 있을 때만 깨어나거나, 끌 수 있는 스위치 하나.

---

## 7. 후처리(톤매핑) — 진짜 해법이 있다

문서 §6: *「꾸러미로는 못 맞춘다」*

월드 판을 **오버레이 카메라**로 따로 그리면 톤매핑을 안 탄다.
URP 에서 카메라 스택을 쓰면 판만 후처리 밖에 둘 수 있다. 못 맞추는 것이 아니라
**안 맞춰 둔 것**에 가깝다 — 사건마다 Volume 이 다른 것은 앞으로도 계속 그럴 테니
이건 꾸러미가 푸는 편이 낫다.

# 우리(옹고집)가 이미 한 일 — 그쪽은 안 고쳐도 되는 것

| 무엇 | 어떻게 |
|---|---|
| 마이크 다툼 | `IMUNROK.Common.MicHold` 걸쇠. 소리계가 그것을 보고 비켜선다. 꾸러미가 §1 을 하면 이어 준다 |
| 글꼴 두 벌 | 우리 판(legacy `UI.Text`)은 `.otf`, 꾸러미 판(TMP)은 `.ttf` 로 **그대로 둔다**. 씬은 안 건드렸다 |
| TMP 에셋 `.meta` | `.gitignore` 를 확장자 기준으로 고쳐 한 겹 아래도 커밋되게 했다 |

# 우리가 안 쓰기로 한 것 — 참고

겹치는 것이 있어 전부를 갈아 끼우지는 않는다. **받는 것**과 **안 받는 것**:

| 받는다 | 왜 |
|---|---|
| `DialogueUI` 하단바 | 치수와 **VR 최소 글씨각 1.30°** 가 실측값이다. 우리 심문 패널은 심문 전용이고 자막은 한 줄이다 |
| `InventoryPreview` (3D 회전) | 우리에게 없다. 물증을 돌려 보는 것은 추리물에서 값이 크다 |
| `UiTuning` 의 벽 회피 + 배율 축소 | 우리 `WorldHudAnchor` 에 없다. 좁은 방에서 판이 벽에 파묻힌다 |
| `UiFontBaker` · 한글 줄바꿈 규칙 | 「첫 프레임 네모 번쩍임」은 우리도 겪는다 |

| 안 받는다 | 왜 |
|---|---|
| `InventoryUI` | 우리 수첩에는 **사건별 물증·제시** 가 붙어 있다. 갈아 끼우면 심문의 「물증으로 묻는다」가 끊긴다 |
| `Interactable` · `UiPointer` · `DebugWalkController` | 도구·돋보기·등불·문이 전부 우리 `ISelectable`·`VRRig` 에 매여 있다 |
| `VoiceInput` | `MicInput`(Wit.ai)이 이미 돈다 |
