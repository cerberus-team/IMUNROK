① 월드 <-> 디테일 셀 변환식   ★배열은 [y, x] 순서 (alphamap 과 같다)

  DR   = terrainData.detailResolution      = 2048
  size = terrainData.size                  = (1000, 300, 1000)
  tpos = terrain.transform.position        = (0, 0, 0)

  셀 -> 월드 (셀 중심)
     wx = (dx + 0.5) / DR * size.x + tpos.x
     wz = (dy + 0.5) / DR * size.z + tpos.z

  월드 -> 셀
     dx = floor( (wx - tpos.x) / size.x * DR )
     dy = floor( (wz - tpos.z) / size.z * DR )

  읽기/쓰기
     int[,] a = td.GetDetailLayer(xBase, yBase, width, height, layer);   // a[y, x]
     td.SetDetailLayer(xBase, yBase, layer, a);

  ★값의 의미 — td.detailScatterMode == CoverageMode
     레이어 값 0~255 는 ★개수가 아니라 ★피복률이다 (255 = 100%).
     실제 개체 수는 DetailPrototype.density (100% 피복일 때 m^2당 개수) 가 정한다.
     현재 최대값은 216 (= 255 / 1.18, 밀도 변조 +-18% 가 255 를 넘지 않게 한 것)

⑤ ★런타임 주의

  SetDetailLayer 로 ★한 셀만 바꿔도 그 셀이 속한 ★패치(64x64 셀 = 31.25 m) 전체의
  개체 배치가 다시 뿌려진다. Phase 1 에서 실측 확인했다.
  -> 단서는 ★미리 구워둘 것. 플레이 중에 파면 그 일대가 통째로 재배치되어 눈에 띈다.
  -> 굳이 런타임에 해야 한다면 그 패치를 시야 밖에 두고 해야 한다.

  ★검증 절차 (Phase 2 에서 쓴 것)
    1) 대상 셀 범위의 레이어 1~8 을 GetDetailLayer 로 백업
    2) 0 으로 SetDetailLayer
    3) 촬영 / 측정
    4) 백업을 SetDetailLayer 로 되돌리고 ★합계가 같은지 확인

  ★이유 — 눈높이 1.6 m 에서 25 m 앞 지면을 보는 시선은 15.3 m 지점에서
    이미 지면 위 0.62 m 로 내려온다. 꽃 높이가 0.34~0.62 m + 메시 1.3~1.6 m 이므로
    ★15 m ~ 25 m 사이의 꽃이 시선을 가로막아 구멍 바닥이 안 보인다.
    거리에서 단서를 보이게 하려면 (a) 구멍을 4 m 이상으로 키우거나
    (b) 길·구역 가장자리에 두거나 (c) 플레이어가 6 m 안으로 들어오게 설계해야 한다.
