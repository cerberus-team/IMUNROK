[1] ★Apply() 가 하드코딩하던 것 (이 라운드의 기술적 장애물)

  FlowerfieldSkyController.Apply() 안에
     RenderSettings.fog = true;                                  (298행)
     RenderSettings.ambientMode = AmbientMode.Skybox;             (304행)
  이 하드코딩돼 있어 바깥에서 RenderSettings 에 써도 ★다음 LateUpdate 에 되돌아갔다
  ([ExecuteAlways] 라 에디터에서도 매 프레임 돈다).
  프리셋에는 fog on/off 도 ambientMode 도 필드가 없었다.
  ★그래서 컨트롤러에 필드 4개를 추가했다 (기존 동작은 기본값 그대로 유지):
     public bool  fogEnabled       = true
     public bool  overrideAmbient  = false
     public Color ambientFlatColor = (0.62, 0.64, 0.60)
     public float ambientFlatScale = 1.5769
  Apply() 는
     RenderSettings.fog = fogEnabled;
     if (overrideAmbient) { ambientMode = Flat; ambientLight = ambientFlatColor * ambientFlatScale; }
     else                 { ambientMode = Skybox; ambientIntensity = Lerp(...); }
  ★원본은 Scripts/_bk/FlowerfieldSkyController_PRE_S22_20260824_2210.cs.txt 에 보존

  ★산괴는 RenderSettings.fog 와 무관하지만 ★프리셋 fogStart/fogEnd 에는 의존한다
     (ApplyMassifFog 가 그 두 값으로 직접 틴트를 계산한다. 365행)
     실측 : fogStart/End 를 900/2500 으로 바꾸면 산괴 휘도 0.5853 -> 0.4172,
            채도 0.1533 -> 0.3308 으로 ★크게 변한다.
            반면 RenderSettings.fog=false 는 산괴에 ★영향 0.
     -> 그래서 A1(fog off)을 택하고 fogStart/fogEnd 는 350/900 그대로 두었다

[2] 측정 방법에서 두 번 틀렸던 것

  ① 등휘도 배율을 ★선형으로 풀었더니 46~60 % 빗나갔다.
     RenderSettings 의 앰비언트 색은 ★감마 공간이다 -> 선형 휘도는 배율의 ★2.2 제곱.
     배율 s = ((L_target - L_black) / (L_k1 - L_black)) ^ (1/2.2) 로 풀어야 한다.
     고친 뒤 등휘도 오차 ★-0.01 %.
  ② 같은 상태의 B0 를 세 번 쟀는데 0.1891 / 0.1763 / 0.1262 로 달랐다.
     원인은 렌더 지연이 아니라 ★마스크가 달랐던 것 (버드나무 포함 여부).
     DynamicGI.UpdateEnvironment() 는 ★지연 없이 다음 cam.Render() 에 반영된다
     (같은 상태 연속 5장이 소수 5자리까지 동일함을 확인).
     -> 마스크는 ★terrain / willow / massif / planet / sky 5분할로 고정하고 파일에 저장
