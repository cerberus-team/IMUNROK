# 이문록(異聞錄) — 공통 시스템 팀원 연동 가이드

> 대상: 각 사건 씬(옹고집전 / 서천꽃밭 / 견우직녀)을 만드는 팀원
> 공통 파트: 조사청(허브) · 복명(엔딩) · 게임 상태(GameState)

이 문서만 보면 여러분의 사건 씬에서 **판결을 어떻게 기록하는지** 알 수 있습니다.
사건 내부의 결말이 몇 개든, 마지막에 **아래 한 줄만 호출**하면 공통 시스템이 나머지(진행도, 세계 열림, 엔딩 분기)를 알아서 처리합니다.

---

## 1. 가장 중요한 한 줄

여러분 사건이 끝나 플레이어가 판결을 내렸을 때, 이렇게 호출하세요:

```csharp
using IMUNROK.Common;

// 예: 옹고집전에서 정상참작으로 판결한 경우
GameState.Instance.SetVerdict(CaseId.Case1_Onggojip, Verdict.Mercy);
```

이 한 줄이 하는 일:
- 그 사건을 **완료(Completed)** 상태로 바꾸고
- 조사청 사건 큐브를 **금색**으로 바꾸고
- 기록대에 **판결패**를 쌓고
- 세 사건이 다 완료되면 **세계 열림 → 봉서함 활성화 → 복명(엔딩)** 으로 이어지게 함

> `GameState.Instance` 는 씬에 아무것도 안 놔도 자동 생성됩니다. 그냥 호출하면 됩니다.
> 상태는 `DontDestroyOnLoad` 로 **씬이 바뀌어도 유지**됩니다.

---

## 2. 사건 매핑 (CaseId)

| CaseId | 사건 | 담당 폴더 |
|---|---|---|
| `CaseId.Case1_Onggojip` | 제1사건 · 옹고집전 — 누가 진짜인가 | `_Project/Onggojip` |
| `CaseId.Case2_Seocheon` | 제2사건 · 서천꽃밭 — 네 번째 환생자 | `_Project/Seocheon` |
| `CaseId.Case3_Gyeonu`   | 제3사건 · 견우직녀 — 칠석 실종 사건 | `_Project/Gyeonu` |

**본인 사건의 CaseId를 정확히 넣어 호출**하세요.

---

## 3. 판결(Verdict)의 의미

판결은 **공통 약속**입니다. 사건 내부 결말이 5개든 2개든, 최종적으로 아래 **셋 중 하나로 "번역"**해서 기록하세요. 왕의 엔딩 총평이 이 셋의 경향으로 갈립니다.

| Verdict | 뜻 | 엔딩에서 |
|---|---|---|
| `Verdict.Truth` | 진실대로 고함 | "사실만을 좇았다" 계열 총평 |
| `Verdict.Mercy` | 정상 참작 | "사람의 사정을 보았다" 계열 |
| `Verdict.AcceptFake` | 갑(甲)을 진짜로 인정 | "설화가 덮은 것을 그대로 두었다" 계열 |

- 세 판결 중 **최다가 2개 이상**이면 그 경향의 총평, **셋이 제각각**이면 혼합 총평.
- 즉, 공통 시스템은 여러분 사건의 세세한 결말은 몰라도 됩니다. **경향(위 3종) 하나만** 넘겨주세요.
- 나중에 사건별 상세 결말을 따로 저장해야 하면, 공통 파트에 `outcomeCode` 슬롯을 추가로 넣을 수 있습니다(현재는 미구현, 필요 시 요청).

---

## 4. (선택) 진행 중 표시

사건 씬에 진입한 순간 조사청 큐브를 **주황색(진행중)**으로 만들고 싶으면(보통 허브가 자동 처리하므로 필수는 아님):

```csharp
GameState.Instance.StartCase(CaseId.Case2_Seocheon);
```

## 5. 제1사건(옹고집) 전용 — 갑리 처리 여부

옹고집전에는 "갑리(가짜)를 처결했는가"를 기록하는 전용 값이 있습니다. 엔딩 대사에 반영됩니다.

```csharp
GameState.Instance.SetGapriHandled(true);  // 갑리를 처결함
```

---

## 6. 씬 흐름과 씬 이름 규약

```
HubScene(조사청)  ──선택──▶  [본인 사건 씬]  ──판결 후 복귀──▶  HubScene  ──세 개 완료──▶  EndingScene(복명)
```

- 조사청의 사건 큐브를 선택하면 **아래 이름의 씬을 자동 로드**합니다. 여러분의 씬 파일명을 이렇게 맞춰 주세요(대소문자 포함):
  - 제1사건: `Onggojip`
  - 제2사건: `Seocheon`
  - 제3사건: `Gyeonu`
- 만든 씬을 **File ▸ Build Profiles/Settings 의 Scene List에 추가**해야 이름으로 로드됩니다. (아직 씬이 없으면 큐브 선택 시 콘솔 로그만 남고 넘어갑니다 — 정상)
- 사건이 끝나면 조사청으로 복귀: `UnityEngine.SceneManagement.SceneManager.LoadScene("HubScene");`
  (판결을 `SetVerdict`로 이미 기록했으면 복귀 시 큐브가 금색, 기록대에 판결패가 쌓여 있습니다.)

## 7. 상태값 읽기 (필요 시)

```csharp
CaseStatus s = GameState.Instance.GetStatus(CaseId.Case1_Onggojip); // NotStarted / InProgress / Completed
Verdict    v = GameState.Instance.GetVerdict(CaseId.Case1_Onggojip);
int   done   = GameState.Instance.CompletedCount;      // 완료된 사건 수
bool  allDone= GameState.Instance.AllCasesCompleted;   // 셋 다 완료?
```

## 8. VR 없이 테스트하는 법 (디버그 모드)

조사청 씬에 `_DebugTester` 오브젝트가 있습니다. Play 후 키보드로:

| 키 | 동작 |
|---|---|
| `1` / `2` / `3` | 대상 사건 선택 |
| `S` | 선택 사건 진행중(StartCase) |
| `T` / `M` / `F` | 판결 Truth / Mercy / AcceptFake 기록 |
| `G` | 갑리 처리 토글(제1사건) |
| `R` | 전체 초기화 |
| 마우스 우클릭 + `WASD` | 방 안 자유 이동(비행 카메라) |
| 마우스 좌클릭 | 사건 큐브/봉서함 선택 |

화면 좌상단 오버레이로 현재 상태를 실시간 확인할 수 있습니다.

## 9. 씬 생성 메뉴 (공통 파트)

상단 메뉴 **`이문록`** 에서:
- `조사청 씬 생성 (HubScene)` — 조사청을 프리미티브로 재생성
- `복명 씬 생성 (EndingScene)` — 엔딩 씬 생성

> 공통 씬은 프리미티브 프로토타입입니다. 손으로 크게 고치기보다, 로직은 스크립트로 두고 이 메뉴로 재생성하는 것을 권장합니다. 실제 에셋은 이후 교체합니다.

## 10. VR / 상호작용 (현재 상태)

- 지금은 **헤드셋 없이** 마우스·키보드로 테스트 중입니다. 코드는 VR 전제로 짜여 있습니다.
- 선택 대상은 `ISelectable`(OnHoverEnter/Exit/Select)로 추상화되어 있어, 나중에 Meta **Building Blocks**의 레이 인터랙터를 붙이면 `VRSelectableBridge`로 연결만 하면 됩니다. **선택 로직은 그대로 유지**됩니다.

## 11. 알려진 제약 (배포 전 해결 예정)

- **자막이 지금은 `OnGUI`** 로 그려집니다. **에디터에선 한글이 보이지만, 빌드(APK)에선 한글이 안 나올 수 있음** → 최종 전에 **TMP + 한글 폰트 에셋**으로 교체 예정.
- `GameState`는 앱 실행 중에만 유지됩니다(세이브 미구현).

## 12. 공통 도구 — 수첩(단서 기록)과 살펴보기

### 수첩(Journal) — 발견한 단서 기록
`GameState`처럼 씬을 넘어가도 유지되는 단서 저장소입니다.

```csharp
using IMUNROK.Common;

// 단서 기록(같은 key는 중복 없이 한 번만)
Journal.Instance.AddClue(CaseId.Case1_Onggojip, "mole", "진짜 옹고집의 점은 왼뺨에 있다.");

// 간단히(문구가 곧 key)
Journal.Instance.AddClue(CaseId.Case1_Onggojip, "부인은 두 사람을 구별하지 못했다.");

// 조회
bool has = Journal.Instance.HasClue(CaseId.Case1_Onggojip, "mole");
int  n   = Journal.Instance.ClueCount(CaseId.Case1_Onggojip);
```

### 살펴보기(IInspectable / InspectableNote) — 확대경으로 보면 정보 표시
"살펴보면 정보가 뜬다"는 **틀**은 공통, **내용**은 여러분이 채웁니다.

- **코드 없이**: 단서 오브젝트(콜라이더 필요)에 `InspectableNote` 컴포넌트를 붙이고 Title/Body 입력.
  - `Record Clue` 체크 + Clue Case/Key/Text 입력 → 살펴본 순간 수첩에 **자동 기록**.
- **직접 구현**: `IInspectable` 인터페이스(`GetInspectTitle`/`GetInspectBody`/`OnInspected`)를 구현해 원하는 동작.

> 지금은 마우스로 가리키면 정보가 뜨고(테스트), VR에선 확대경을 든 손이 같은 계약을 호출합니다.
> 조사청에 `SampleInspectable`(데모)이 하나 있으니 참고해서 교체하세요.

디버그: 조사청에서 `C` 키 = 대상 사건에 샘플 단서 기록, 좌상단 오버레이에 사건별 단서 수 표시.
